# Сравнение вариантов решения

## Критерии

Для предварительной оценки решений использовались следующие критерии:

| Критерий | Почему важен |
|---|---|
| Мобильное приложение | Менеджер работает непосредственно на выставочной площадке |
| Работа офлайн | Интернет на площадке может быть нестабильным или отсутствовать |
| Локальная клиентская база | Поиск должен оставаться доступным без соединения |
| Поиск по нескольким параметрам | Менеджер может знать только часть данных клиента |
| Быстрый поиск | Клиента необходимо найти и открыть не более чем за 30 секунд |
| Работа с карточкой клиента | Необходимо просматривать историю и фиксировать результат встречи |
| Создание нового клиента | Новый контакт должен быть сохранён непосредственно во время встречи |
| Синхронизация | Данные, созданные офлайн, должны передаваться после восстановления связи |
| Работа с материалами | Менеджер должен иметь возможность выбрать материалы для клиента |
| Возможность доработки | Часть требований может отсутствовать в стандартной конфигурации |

## Предварительный анализ

| Решение | Мобильная работа | Офлайн-сценарий | Работа с клиентской базой | Материалы | Комментарий |
|---|---|---|---|---|---|
| BPMSoft | Требует проверки | Требует уточнения у поставщика | Рассматривалось | Требует проверки | Необходима детальная проверка мобильного сценария |
| ST-Mobi | Рассматривалось | Один из ключевых вопросов анализа | Рассматривалось | Требует проверки | Интерес представляли возможности мобильной работы |
| 1С Mobile | Рассматривалось | Потенциально возможно | Требует настройки под модель данных | Требует проектирования | Более гибкий вариант, но требует отдельной оценки объёма разработки |
| amoCRM | Мобильное приложение есть | Требует проверки полного офлайн-сценария | Рассматривалось | Требует проверки | Важно проверить доступность функций без соединения |
| ConfControl | Рассматривалось для выставочного сценария | Требует проверки | Требует проверки | Рассматривалось | Специализированный вариант, требующий сопоставления с CRM-сценарием |
| LeadFrog | Рассматривалось | Требует проверки | Ограниченный сценарий требовал дополнительной оценки | Рассматривалось | Отдельные механизмы коммуникации не полностью соответствовали требованиям проекта |

> Таблица отражает этап предварительного анализа. Финальная оценка решения должна выполняться после демонстрации поставщика и проверки требований MVP.

## Вопросы поставщикам

При общении с поставщиками необходимо было уточнить:

- доступна ли клиентская база без интернет-соединения;
- какие данные сохраняются локально;
- по каким полям работает поиск;
- поддерживается ли частичный поиск;
- можно ли создавать карточки и комментарии офлайн;
- как разрешаются конфликты при синхронизации;
- что происходит с несинхронизированными данными после закрытия приложения;
- можно ли выбрать маркетинговые материалы без интернета;
- как организована последующая отправка материалов клиенту;
- какие функции доступны в стандартной версии, а какие требуют доработки;
- какие ограничения существуют по числу пользователей и объёму данных.

## Вывод

Главным фильтром при выборе решения стала возможность выполнить полный основной сценарий менеджера с мобильного устройства даже при нестабильном соединении.

Само наличие мобильного приложения не гарантирует соответствия требованиям проекта: отдельно необходимо проверять локальное хранение данных, поиск, создание и изменение записей, а также последующую синхронизацию.
