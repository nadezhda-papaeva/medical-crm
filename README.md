# Мобильная CRM для дистрибьютора офтальмологического оборудования

## О проекте

Компания — дистрибьютор дорогостоящего офтальмологического оборудования, работающий с клиниками и медицинскими организациями.

Одним из важных каналов привлечения потенциальных клиентов являются профильные медицинские выставки. Привлечение таких контактов требует значительных затрат, поэтому для бизнеса особенно важно не терять информацию о потенциальных клиентах и эффективно использовать каждое взаимодействие.

Во время выставки менеджеру необходимо быстро найти информацию о клиенте, посмотреть историю предыдущих взаимодействий, оставить комментарий после общения или создать новую карточку клиента.

Критичное требование проекта — поиск информации о клиенте должен занимать не более 30 секунд.

Название компании и отдельные детали проекта не раскрываются в целях сохранения конфиденциальности.

## Бизнес-проблема

Во время профильных выставок менеджеры работают в условиях большого потока посетителей и ограниченного времени на общение.

При встрече с представителем клиники менеджеру необходимо быстро определить:

- есть ли этот клиент в базе;
- взаимодействовала ли компания с ним ранее;
- какая информация о предыдущих контактах уже зафиксирована;
- нужно ли создать нового клиента;
- какие результаты текущей встречи необходимо сохранить.

Существующий процесс не обеспечивал достаточно быстрого и удобного доступа к данным в условиях выставки.

Длительный поиск информации затрудняет общение с потенциальным клиентом и увеличивает риск потери ценного контакта.

Бизнесу необходимо было решение, которое позволило бы менеджеру получить доступ к клиентской информации непосредственно во время встречи и сразу зафиксировать результат общения.

## Цель проекта

Подобрать и проработать мобильное решение, которое позволит менеджерам по продажам быстро работать с клиентской базой во время профильных выставок.

Основные цели:

- сократить время поиска информации о клиенте;
- обеспечить менеджеру доступ к клиентской базе с мобильного устройства;
- упростить фиксацию результатов встречи;
- снизить риск потери информации о новых потенциальных клиентах;
- обеспечить возможность работы при нестабильном или отсутствующем интернет-соединении.

## Пользователи

Основные пользователи решения:

- менеджеры по продажам офтальмологического оборудования;
- сотрудники компании, представляющие ее на профильных медицинских выставках.

## AS-IS / TO-BE

### AS-IS — текущий процесс

Во время профильной выставки менеджер общается с представителем клиники и должен определить, есть ли этот контакт в клиентской базе и взаимодействовала ли компания с ним ранее.

Для этого менеджеру необходимо:

1. Получить данные потенциального клиента.
2. Проверить наличие клиента в существующей базе.
3. Найти информацию о предыдущих взаимодействиях.
4. Зафиксировать результаты новой встречи.
5. При отсутствии клиента создать новую карточку.

Существующий процесс не обеспечивает достаточно быстрого и удобного доступа к информации с мобильного устройства непосредственно во время общения.

Основные проблемы AS-IS:

- поиск информации может занимать слишком много времени;
- доступ к клиентской информации недостаточно удобен в условиях выставки;
- менеджеру сложно оперативно проверить историю взаимодействия;
- фиксация результатов встречи может происходить не сразу;
- существует риск потери информации о новом контакте;
- качество интернет-соединения на площадке может быть нестабильным.

### TO-BE — целевой процесс

Менеджер получает доступ к мобильному приложению, через которое может работать с клиентской базой непосредственно во время выставки.

Целевой процесс:

1. Менеджер вводит известные данные клиента:
   - фамилию;
   - название клиники;
   - номер телефона;
   - электронную почту.
2. Система выполняет поиск по клиентской базе.
3. Результат поиска отображается не более чем за 30 секунд.
4. Если клиент найден, менеджер:
   - открывает карточку клиента;
   - просматривает доступную информацию;
   - изучает историю предыдущих взаимодействий;
   - добавляет комментарий по итогам текущей встречи.
5. Если клиент не найден, менеджер создает новую карточку.
6. Информация сохраняется для дальнейшей работы с потенциальным клиентом.

Решение должно поддерживать работу как при наличии интернет-соединения, так и без него.

### Изменение процесса

| AS-IS | TO-BE |
|---|---|
| Доступ к информации неудобен в условиях выставки | Данные доступны через мобильное приложение |
| Поиск может занимать слишком много времени | Поиск занимает не более 30 секунд |
| Историю взаимодействия сложно оперативно проверить | Информация доступна непосредственно во время встречи |
| Результат встречи может фиксироваться позже | Комментарий можно добавить сразу после общения |
| Новый контакт может быть временно записан вне системы | Новую карточку можно создать непосредственно в приложении |
| Работа зависит от качества интернет-соединения | Предусмотрена возможность работы офлайн |

## Основные требования

### Поиск клиента

Система должна позволять выполнять поиск клиента по:

- фамилии;
- названию клиники;
- номеру телефона;
- электронной почте.

Результат поиска должен быть получен не более чем за 30 секунд.

### Работа с существующим клиентом

После нахождения клиента пользователь должен иметь возможность:

- открыть карточку клиента;
- просмотреть доступную информацию;
- посмотреть данные о предыдущих взаимодействиях;
- добавить новый комментарий по итогам встречи.

### Работа с новым клиентом

Если клиент отсутствует в базе, менеджер должен иметь возможность:

- создать новую карточку;
- внести основные контактные данные;
- сохранить информацию для дальнейшей работы.

### Работа без интернет-соединения

Система должна обеспечивать возможность выполнения основных сценариев при отсутствии или нестабильном интернет-соединении.

После восстановления соединения новые или измененные данные должны быть доступны для дальнейшей работы в системе.

## MVP

В MVP были включены функции, необходимые менеджеру непосредственно во время выставки:

- поиск клиента по нескольким параметрам;
- просмотр карточки клиента;
- просмотр доступной информации о клиенте;
- добавление комментария;
- создание новой карточки клиента;
- работа с мобильного устройства;
- возможность работы онлайн и офлайн;
- выполнение поиска не более чем за 30 секунд.

Дополнительный функционал, не влияющий напрямую на основной сценарий работы менеджера на выставке, рассматривался как второстепенный.

## Рассматриваемые варианты решения

В рамках проекта анализировались готовые CRM и мобильные решения, которые потенциально могли закрыть потребности бизнеса.

При сравнении вариантов учитывались:

- скорость поиска;
- возможность поиска по нескольким параметрам;
- наличие мобильного приложения;
- возможность работы офлайн;
- удобство создания и изменения карточки клиента;
- возможность интеграции с существующей инфраструктурой;
- сложность внедрения;
- соответствие требованиям MVP.

По результатам анализа отдельные варианты были вынесены на дополнительное обсуждение с поставщиками.
